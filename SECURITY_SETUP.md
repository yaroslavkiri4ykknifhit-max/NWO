# Защищённый доступ NWO на GitHub Pages

## Как устроена защита

GitHub Pages публикует только статический интерфейс. В сборке `out` нет текстов платного курса, инвайт-кодов, токена Telegram-бота или секрета подписи.

Google Apps Script выполняет роль закрытого хранилища материалов и авторизации:

1. Пользователь подтверждает личность через официальный Telegram Login Widget.
2. При первой авторизации вводит индивидуальный инвайт-код.
3. Apps Script проверяет подпись Telegram, статус и срок доступа, привязывает код к неизменяемому Telegram ID и выдаёт HMAC-подписанную сессию на 2 часа.
4. При каждом запросе уроков, разборов или сохранении прогресса Apps Script снова проверяет подпись сессии, Telegram ID, `access_status` и `expires_at`.
5. Сессия хранится в `sessionStorage`: переживает перезагрузку вкладки, но удаляется после её закрытия и недоступна другим вкладкам.

Вход только по коду отключён: без подтверждённого Telegram подобрать или передать код недостаточно.

## 1. Обновить Google Apps Script

1. Откройте Google Таблицу → **Расширения → Apps Script**.
2. Замените содержимое `Code.gs` кодом из файла `google-apps-script.js`.
3. Откройте **Project Settings → Script Properties** и добавьте:
   - `SPREADSHEET_ID` — ID таблицы;
   - `TELEGRAM_BOT_TOKEN` — токен бота от BotFather;
   - `SESSION_SECRET` — случайная строка минимум из 32 символов.
4. Секрет можно создать командой `openssl rand -base64 48`.
5. Выберите **Deploy → Manage deployments → Edit → New version → Deploy**.
6. Параметры Web app: **Execute as Me**, доступ **Anyone**.
7. Скопируйте адрес вида `https://script.google.com/macros/s/.../exec`.

`SESSION_SECRET` нельзя добавлять в GitHub, клиентский JavaScript или Google Таблицу. Он хранится только в Script Properties.

## 2. Настроить таблицу

Скрипт автоматически добавит в `Invites` недостающие колонки:

- `code_hash` — SHA-256 инвайт-кода;
- `telegram_id` и `telegram_username`;
- `completed_lessons`;
- `access_status`;
- `expires_at`.

Активные статусы: `active`, `paid`, `trial`. Пустая ячейка, значения `revoked`, `refunded`, `blocked` и любые другие сразу закрывают материалы даже при ещё действующей сессии. Некорректная дата `expires_at` также закрывает доступ.

Для новых покупателей используйте случайные коды длиной не менее 24 символов. Исходный код покажите покупателю один раз, а в таблице храните только его SHA-256 в `code_hash`. Встроенная функция `logInviteCodeHash` помогает получить хеш.

Старые коды продолжат работать: после первой успешной активации скрипт заполнит `code_hash`. Затем исходный код можно удалить из колонки `code`, предварительно сохранив резервную копию.

## 3. Настроить GitHub Pages

В репозитории откройте **Settings → Secrets and variables → Actions** и добавьте:

- `NEXT_PUBLIC_APPS_SCRIPT_URL` — URL развёрнутого Apps Script;
- `NEXT_PUBLIC_TELEGRAM_BOT_NAME` — имя бота без `@`.

URL Apps Script и имя бота не являются секретами. Уроки по этому URL без корректной подписанной сессии не выдаются.

В **Settings → Pages → Build and deployment** выберите **GitHub Actions**. Workflow `.github/workflows/deploy.yml` соберёт статический `out` и опубликует его на Pages. Домен `newwayout.online` можно оставить подключённым как сейчас.

## 4. Подключение оплаты позже

Секрет платёжной системы нельзя помещать в GitHub Pages. Webhook оплаты должен приходить в Google Apps Script, проверять подпись платёжного провайдера и только после этого обновлять строку `Invites`: `code_hash`, `access_status=paid`, `expires_at`.

Ответ браузера «оплата прошла» никогда не должен самостоятельно включать доступ. При возврате платежа webhook ставит `refunded`, и материалы закрываются при следующем запросе.

## Честные ограничения GitHub Pages

У статического сайта нет `HttpOnly` cookie и возможности выставлять собственные HTTP security headers. Подписанный токен приходится хранить в памяти браузера, поэтому эта схема слабее полноценного серверного приложения. Токен короткоживущий, не содержит исходный инвайт-код и бесполезен после блокировки строки в таблице.

Также невозможно запретить легальному покупателю сделать скриншот, запись экрана или скопировать открытую ссылку YouTube/Vimeo/Google Drive. Для дорогого видео понадобится видеохостинг с короткоживущими подписанными ссылками или DRM.
